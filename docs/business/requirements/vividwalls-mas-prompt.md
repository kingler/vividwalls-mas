Multiagent Business Management System (MAS) for VividWalls – Specification

System Overview

Purpose of the MAS: The MAS is designed to automate and optimize the operations of VividWalls’ e-commerce business by delegating tasks to specialized AI agents. By orchestrating a team of domain-specific AI agents as a unified system, the business can handle complex workflows in marketing, sales, fulfillment, and customer service with minimal human intervention ￼ ￼. This autonomous system aims to increase efficiency (e.g. faster campaign execution, instant customer support) and ensure consistent decision-making aligned with the brand’s strategy.

Platform & Product Description (VividWalls): VividWalls (vividwalls.co) is an online platform selling limited-edition, numbered, ready-to-hang art prints signed by artists. Each artwork is produced on demand with high-quality printing and framing, then shipped directly to customers. The store’s value proposition lies in offering exclusive artwork in gallery-quality formats without maintaining physical inventory – prints are fulfilled on-demand via a print partner (Pictorem). This means VividWalls can offer a “wide variety of customized artwork” with “on-demand, online fine art printing, fulfillment and shipping”, all with no inventory or minimum orders ￼. The MAS will manage this operation end-to-end: from creating marketing campaigns that drive traffic, to processing orders and coordinating their fulfillment, to engaging customers for sales and support.

General Architecture: The system is composed of multiple intelligent agents, each powered by large language models (LLMs) with tool-use capabilities, working in concert. These agents function as the “brain” for different business domains (marketing, sales, operations, etc.) but are connected through a central workflow orchestrator (n8n). The n8n workflows act as the automation spine, triggering agents based on schedule or events and passing data between them. This architecture combines the decision-making prowess of LLM agents with n8n’s integration capabilities to execute actions on external services ￼. Agents do not operate in isolation; the Business Manager Agent serves as a coordinating hub, delegating tasks to specialized agents and ensuring their outputs align with overall business goals. All agents utilize Model Context Protocol (MCP) servers (for Shopify, Pictorem, Facebook Ads, etc.) to perform actions via function calls embedded in prompts. MCP standardizes how external data and operations are exposed to AI models, providing a structured interface to commerce platforms ￼ ￼. Each agent’s prompt contains instructions and tool definitions (MCP functions) that allow the LLM to retrieve data or execute operations (e.g. fetching Shopify orders, creating a Facebook ad) as part of its reasoning. The agents achieve a level of prompt-based autonomy: given high-level objectives or triggers, they decide on sub-tasks, invoke the appropriate MCP tools through formatted function calls, and produce results or further instructions. The overall MAS thus operates as an intelligent, event-driven workflow system: n8n triggers set the agents into motion, agents use tools to interface with real data/systems, and their decisions feed into subsequent actions – creating a closed-loop business management process.

Agent Roles

Business Manager Agent

Role/Purpose: Acts as the central orchestrator and executive of the multi-agent system. This agent has a high-level view of business operations and is responsible for delegating tasks to the appropriate specialized agents. It ensures that marketing, sales, fulfillment, and customer service activities all align with VividWalls’ business objectives (sales targets, brand image, customer satisfaction).

Key Responsibilities:
	•	Strategic Decision-Making: Continuously monitors business metrics (sales trends, website traffic, inventory levels, campaign performance) and decides on strategic actions. For example, the Business Manager might notice a drop in sales and initiate a new marketing campaign, or identify a top-selling collection and suggest increasing its promotion. It uses data from Shopify (orders, product stats) and possibly analytics tools to make informed decisions.
	•	Workflow Delegation: Initiates and coordinates workflows by instructing other agents. It triggers the Marketing Research Agent on a schedule (e.g. the first of each month) or when a new product collection is added, asking for market analysis or campaign ideas. It delegates campaign execution to the Marketing Campaign Agent once a plan is approved. For fulfillment, upon receiving new order events, it can signal the Pictorem Agent to process the order. In essence, the Business Manager agent is the hub that receives trigger signals (time-based or event-based via n8n) and routes tasks to the relevant agents in the correct sequence.
	•	Inter-Agent Coordination: Communicates context and objectives to specialized agents and consolidates their outputs. For example, if the Marketing Research agent produces a 3-month campaign plan, the Business Manager reviews it (ensuring it fits budget or brand guidelines) and then instructs the Marketing Campaign agent to implement it. It might pass along relevant data (like which art collections to focus on, or sales figures the research agent should consider). Similarly, it ensures the Customer Relationship Agent’s insights (e.g. VIP customer lists or feedback summaries) are fed to the Sales and Customer Service agents. The Business Manager does not execute low-level actions itself; rather, it makes high-level decisions and relies on other agents (and their tool use) for execution.
	•	Exception Handling & Oversight: Monitors the outputs of all agents for quality and consistency. If an agent’s outcome isn’t satisfactory (e.g. a marketing campaign underperforms or a customer issue remains unresolved), the Business Manager can adjust the strategy or redirect agents to follow up. It may flag issues for human review when necessary. Essentially, this agent provides a supervisory layer, akin to a manager reviewing the work of a team of assistants.

Marketing Research Agent

Role/Purpose: Serves as the trend analyst and planner for marketing. This agent’s primary job is to research the art market and digital marketing trends to ideate effective campaigns for the coming months. It focuses on high-level marketing strategy, ensuring VividWalls’ advertising efforts align with current trends and consumer interests in art and home decor.

Key Responsibilities:
	•	Monthly Trend Analysis: On a scheduled basis (e.g. monthly or quarterly), this agent is triggered to analyze both internal data and external trends. It might review VividWalls’ recent sales data (via Shopify tools) to see which art styles or collections are performing well, and combine that with external market research – for example, identifying seasonal decor trends, popular color schemes, or trending topics in art and interior design. If integrated with external data sources, it could use web search or social media trend analysis to find what art or design content is getting attention (for instance, noting if “minimalist art” or “geometric prints” are currently popular). The agent then extracts insights to inform marketing.
	•	Campaign Ideation (3-Month Plan): Using the trend analysis, the Marketing Research Agent crafts a forward-looking marketing plan, typically spanning the next quarter (3 months). This plan includes campaign concepts, themes, and rough timelines. For example, it might propose: “In October, run a ‘Autumn Art Refresh’ campaign focusing on warm-toned prints; in November, a holiday gifting campaign highlighting limited-edition pieces as unique gifts; in December, a New Year/New Art campaign.” For each proposed campaign, it outlines key messages, target audience insights, and which product collections to feature. The agent essentially produces a marketing roadmap that anticipates upcoming opportunities (holidays, seasons, art events) and aligns them with VividWalls’ offerings.
	•	Market Research Tools & Data: The agent can utilize available tools to augment its analysis. It may call Shopify MCP functions to pull sales reports or product performance data (e.g. ${get-orders} filtered by date, or ${get-products-by-collection} to see inventory and popularity). It could also use social media MCP servers if available (for instance, a Pinterest or Instagram MCP to see popular pins/posts in art categories) or a general web search tool for market reports. These tool results help ground the agent’s suggestions in data rather than only the LLM’s training knowledge.
	•	Output & Handoff: The deliverable is a structured campaign plan or report, which it passes to the Business Manager agent (likely through n8n). The plan will detail each suggested campaign, rationale, and resource estimates (e.g. recommended ad channels like Facebook vs. Pinterest, budget considerations if known, and content ideas such as which artwork images to feature). The Business Manager typically reviews this plan. If certain ideas don’t fit (e.g. budget or branding constraints), the Business Manager might prompt the Marketing Research agent for revisions or just adjust the plan before sending it on. Once approved, the plan flows to the Marketing Campaign Agent for execution.

Marketing Campaign Agent

Role/Purpose: Functions as the marketing executor, responsible for turning the marketing plans and ideas into live campaigns across social media and ad platforms. Whereas the Marketing Research agent strategizes what to do, the Marketing Campaign agent figures out how to do it on each channel and then uses tools/agents to launch the campaigns. This agent ensures that the campaigns are properly set up, creatives are generated or selected, and budgets and targeting are configured.

Key Responsibilities:
	•	Campaign Strategy Implementation: Upon receiving a campaign brief or plan (from the Marketing Research agent via the Business Manager), this agent breaks it down into actionable tasks. For example, if the plan calls for a Facebook and Instagram ad campaign in October focusing on the “Vivid Mosaics” collection, the Marketing Campaign Agent will determine the specifics: the campaign objective (e.g. website traffic or conversions), target audience (e.g. art enthusiasts, interior designers, lookalike audience of past customers), budget allocation per day, campaign duration, and key messaging. It may also draft the ad copy text and choose which product images or lifestyle images to use in the creatives. Since it’s an LLM, it can generate persuasive ad text given the product details.
	•	Multi-Channel Coordination: This agent orchestrates campaigns on Facebook, Instagram, and Pinterest (the primary channels identified). It interfaces with the dedicated platform agents or MCP tools for each channel:
	•	Facebook/Instagram: Uses the Facebook Ads MCP server via the Facebook Agent (and Instagram Agent if separately needed) to create campaigns, ad sets, and ads. It will call functions like ${create-campaign} with parameters (audience, budget, creative assets, etc.) through the Facebook Agent. The Facebook MCP provides standardized access to ad accounts, campaigns, and insights ￼, so the agent can programmatically set up ads and later fetch their performance. (Instagram ads are managed through the same Meta Ads platform, so they might be created via Facebook’s MCP as well, but if treated separately, the Instagram Agent will handle Instagram-specific posting or story promotions).
	•	Pinterest: Uses the Pinterest Agent (if available) or a Pinterest MCP to create Pins or Promoted Pin campaigns. The agent might schedule a series of pins featuring product images with links back to VividWalls. If a Pinterest Ads MCP tool exists, it can create and target ads similarly to Facebook. If not, a custom integration may be required for posting pins via Pinterest’s API.
	•	Additionally, the Marketing Campaign Agent coordinates the messaging so that there’s consistency across channels (e.g., ensuring a campaign tagline or promo code is the same on Facebook and Pinterest). It may also integrate Shopify into the process for things like generating discount codes or tracking links for the campaigns (for example, calling a Shopify tool to create a unique discount code “AUTUMN10” and then including that code in ad copies or landing pages).
	•	Tool Utilization: This agent heavily uses MCP tools to execute tasks. For instance:
	•	Shopify MCP: to maybe create a new collection on the storefront if needed for a campaign landing page, or to pull product info (images, titles, prices) to include in ads. It could also use Shopify’s discount management tool to set up a special discount (the Shopify MCP supports discount code creation ￼).
	•	Facebook Ads MCP: to create and configure campaigns and ad sets. Through the Facebook Agent, it can set parameters like demographic targeting, upload ad creatives, and start the campaign ￼.
	•	Instagram MCP/API: if doing organic posts or story ads, it might post content (though for Ads it would be via Facebook’s system).
	•	Pinterest MCP/API: to create pins or ads, possibly by selecting images of products and writing pin descriptions that link to the store.
	•	Possibly a Content Creation tool (not explicitly listed, but the LLM itself is generating text like ad copy). If image variations are needed, it might require a designer or an AI image generation tool (not in scope here, presumably they use existing product images).
	•	Campaign Launch & Monitoring: Once the campaigns are set live via the above tools, the Marketing Campaign Agent can either end its task or enter a monitoring mode. In real-time operation, it may rely on the platform-specific agents to monitor performance (see below). However, it could also be scheduled (say, every week or end-of-campaign) to fetch performance data via the MCP tools (like reach, clicks, conversions from Facebook Ads) and compile a brief report for the Business Manager. If results are below expectations, it might suggest adjustments (e.g. increase budget, tweak audience). Major optimizations might be left to the platform agents continuously, but the campaign agent could do high-level adjustments or decide when to terminate or scale campaigns based on ROI.

Shopify Agent

Role/Purpose: Serves as the e-commerce store operations specialist. This agent’s domain is the Shopify backend of VividWalls – it can retrieve and modify data such as products, collections, orders, and customers. Essentially, the Shopify Agent is the interface between the MAS and the Shopify store, empowered by the Shopify MCP tools.

Key Responsibilities:
	•	Product and Collection Management: The agent can create or update product listings and collections on the Shopify store as needed. For example, if a new art print collection (“Geometric Symmetry”) is being launched, the Business Manager or Marketing Campaign agent might task the Shopify Agent with setting up a new collection entry and ensuring all relevant products are included. Using MCP functions, it can retrieve all products in a certain category or with a certain tag and then group them into a collection. It can also update product details (prices, stock status, descriptions) if pricing strategies change or new information needs to be added. The Shopify MCP provides tools to retrieve products (by title, collection, etc.) and manage product variants ￼, which the agent uses for any content or inventory updates.
	•	Order Management and Fulfillment Status: The Shopify Agent can query orders and update their status. It might be invoked to check recent orders (e.g., for generating sales reports or identifying unfulfilled orders). For instance, it can use a get-orders tool to list orders (filtering by date or fulfillment status) and provide that data either to the Business Manager (for analytics) or to the Pictorem Agent (to act on new unfulfilled orders). Additionally, if the Pictorem Agent or fulfillment process provides a tracking number or confirmation, the Shopify Agent could update the order’s fulfillment info via Shopify’s API (mark it as fulfilled and add tracking details). This ensures the Shopify store reflects the true order status, which also triggers Shopify’s customer notification emails, etc.
	•	Customer Data and CRM Support: The agent can pull customer information from Shopify when needed. For example, the Customer Relationship Agent might ask the Shopify Agent for all data on a particular customer (purchase history, total spend, tags) to build a profile. Shopify MCP tools allow loading customer data and even adding tags to customers ￼. The Shopify Agent could be used by the CRM agent to execute tagging (like labeling a customer as “VIP” or “RepeatBuyer” in Shopify for future reference). It might also retrieve a list of all newsletter subscribers or customers in a certain segment if needed for marketing (though that is more in CRM’s purview).
	•	Event Trigger Integration: Through n8n and Shopify webhooks, the Shopify Agent is likely tied to real-time events. For example, when a new order is created on Shopify, a webhook can trigger n8n which in turn engages the Shopify Agent (or directly the Pictorem Agent) to fetch the order details and begin fulfillment. Similarly, when a product’s stock or any relevant data changes, the Shopify Agent could react (though since prints are made on demand, inventory counts might not be critical except maybe limited edition counts). The agent might also be involved in detecting slow-moving inventory (if prints have limited runs, it might identify pieces that haven’t sold recently) to prompt the Business Manager about clearance sales or extra marketing needed.
	•	Support for Other Agents: The Shopify Agent often works behind the scenes, invoked by other agents’ requests for data. For example, the Sales Agent (during a customer chat) might need product details – rather than that agent directly calling the Shopify API, the Shopify Agent can handle the request and return the info to the Sales Agent in a structured way. This separation keeps the Sales Agent focused on dialogue, while the Shopify Agent ensures data accuracy from the source.

Pictorem Agent

Role/Purpose: Handles order fulfillment and print production management. Pictorem is the print-on-demand fulfillment partner for VividWalls, so this agent is responsible for interfacing with Pictorem’s systems to produce and ship the ordered art prints. It acts as a bridge between the Shopify orders and the Pictorem production process, using either Pictorem’s API or automated browser actions to place orders and manage them.

Key Responsibilities:
	•	Order Fulfillment Processing: When a customer places an order on VividWalls (recorded in Shopify), the Pictorem Agent is triggered (likely via an n8n workflow listening to new orders). Its task is to ensure that order is submitted to Pictorem for printing. Using Pictorem’s API, the agent will take the order details (print design, size, frame options, customer shipping address) and call the appropriate endpoint to “send orders automatically, including image download & customer addresses” ￼. Essentially, it programmatically creates an order in Pictorem’s system corresponding to the customer’s purchase. If Pictorem’s API requires the image file, the agent might download the artwork file (possibly from a cloud storage or Shopify’s files) and provide it in the request.
	•	Pricing and Cost Management: Before placing the order, the Pictorem Agent may use Pictorem’s tools to check product base cost and ensure pricing is set for profitability. Pictorem’s API allows retrieving product listing and pricing information ￼. The agent could, for instance, calculate the production cost of a chosen print size/material and compare it to what the customer paid on Shopify. If there’s a discrepancy (say the price was set too low), it could alert the Business Manager or adjust something if within its scope (perhaps adding a rush fee or switching to a cheaper shipping if possible). Additionally, for new products, the Business Manager might consult the Pictorem Agent to set pricing – the agent can fetch Pictorem’s base price for a given size/material and suggest a retail price with a healthy margin.
	•	Order Tracking and Updates: After submitting the order, the agent monitors its status through Pictorem. Using the API, it can poll or receive callbacks for status changes (printing, shipped, delivered). It can fetch the tracking number once the item ships ￼. The Pictorem Agent then updates Shopify via the Shopify Agent or directly (mark order fulfilled, attach tracking info). This closes the fulfillment loop and triggers Shopify to send shipping confirmation to the customer. In case of delays or issues from Pictorem’s side (e.g. out-of-stock materials or print errors), the agent can notify the Customer Service Agent to inform the customer or take corrective action (perhaps switch to a similar print provider if emergency, though that’s beyond current scope).
	•	Automation Method: The Pictorem Agent primarily uses Pictorem’s Full-featured REST API, which provides a standardized way to integrate print-on-demand services ￼. If for any reason the API is insufficient or certain actions aren’t exposed, the agent can fall back to traditional browser automation – essentially controlling a headless browser to log into the Pictorem dashboard and perform tasks like a human would (this could be powered by an LLM’s understanding plus scripted steps). The prompt might guide the agent through the sequence: login, navigate to “Place Order”, fill out forms with the order data, etc. However, the preference is to use the API for reliability.
	•	Inventory and Product Sync: While Pictorem mostly prints on demand, it offers various print formats (canvas, metal, acrylic, etc.). The Pictorem Agent might periodically fetch the list of available product types or any changes in production times/costs. For example, if Pictorem updates the base cost of a 24x36 canvas print, the agent could inform the Business Manager or auto-update the product price on Shopify (via the Shopify Agent) to maintain margins. It could also update the website if certain formats become temporarily unavailable.
	•	Integration with Pricing Tools: The question mentions “pricing tools” – possibly referring to tools to calculate optimal pricing or currency conversion. The Pictorem Agent might incorporate a pricing formula or connect with a pricing optimization tool to ensure each product’s price covers printing cost + shipping + target profit. This could be a custom tool where the agent inputs Pictorem cost and gets a recommended price. The agent can then instruct the Shopify Agent to update the product pricing if needed.

Sales Agent (Inbound Sales Copilot)

Role/Purpose: Acts as a virtual sales representative that engages with potential customers browsing the VividWalls site. Through a chat interface (such as CopilotKit integrated on the Shopify or WordPress pages), this agent converses with visitors in natural language, answers their questions about products or orders, and helps guide them towards making a purchase. The Sales Agent’s ultimate goal is to improve conversion rates by providing real-time, personalized assistance – essentially, it’s the AI shopping assistant for VividWalls.

Key Responsibilities:
	•	Live Customer Engagement: The Sales Agent is integrated into the website’s front-end (e.g., as a chat bubble labeled “Chat with us” on both the Shopify storefront and the WordPress “Art Insights” blog pages). When a visitor asks a question or seeks help, this agent responds immediately, 24/7. It can greet users, ask what they’re looking for, and provide product recommendations. For example, if a user says “I’m looking for a large colorful abstract piece for my living room,” the agent can search the product catalog for suitable prints (using a Shopify MCP tool like get-products with a filter for “abstract” or specific dimensions) and then respond with a few suggestions (including images, titles, prices, and a direct link to the product page). This creates a personalized shopping experience similar to an in-store sales rep suggesting products.
	•	Product Knowledge & Persuasion: The Sales Agent has access to detailed product information. It can pull up an artwork’s description, size options, materials, and availability via Shopify tools. For instance, if asked “Tell me about ‘Red Kimono’ print,” the agent can retrieve that product’s details (title, collection, artist note, price) and summarize it for the customer. It will highlight selling points (e.g. limited-edition status, the fact it’s signed by the artist, the vibrant colors) to entice the customer ￼ ￼. The agent also handles typical buyer questions like “What’s the shipping time?” or “Do you offer discounts?” – it knows general store policy answers (shipping usually within X days, etc.) and can on-the-fly generate a discount code via Shopify if appropriate (for example, if a user is hesitating on a $500 purchase, the agent might offer a 10% off code generated through ${create-discount}). All of this is done in a conversational, helpful tone to build trust.
	•	Cart Assistance and Checkout: If a user shows intent to buy, the Sales Agent can assist with the process. It might add an item to the user’s Shopify cart through an MCP call and provide a checkout link. In a more advanced scenario, if the user agrees, it could even create a draft order via Shopify MCP and send an invoice link. The agent essentially helps reduce friction in the purchase process – for example, it can autofill the cart with the selected print in the desired size and direct the customer straight to the checkout page. This level of service can significantly improve conversion by simplifying steps for the customer.
	•	Inbound Lead Handling on WordPress: The mention of WordPress pages (possibly a blog or landing pages under “Art Insights”) indicates the agent might also pop up there. If someone is reading an art blog post and asks a question (“Do you have pieces similar to this one?”), the Sales Agent can handle it similarly by pulling related products. Being on WordPress might require the agent to have access to the site content (for context) and then link back to products on Shopify. This cross-platform presence ensures wherever the customer interacts (store or blog), the same AI sales assistant is available.
	•	Collaboration with CRM Data: When a known customer logs in or provides their email, the Sales Agent can fetch their profile (via the Customer Relationship Agent’s data or directly from Shopify customer info). It might see tags like “VIP” or notes about past purchases. Using this, the agent can personalize the interaction: “Welcome back, Alice! How do you like the Mosaic piece you bought last month? If you’re looking for something complementary, I can recommend our new Geometric Symmetry collection.” This continuity and personalization (enabled by stored context and tags) echo the omnichannel AI experience where returning customers get tailored treatment ￼ ￼. The Sales Agent ensures that high-value customers get white-glove service, and new customers get informative guidance to build confidence in their purchase.
	•	Escalation for Complex Queries: If a question goes beyond sales (for example, a technical support issue or something the AI is not confident about), the Sales Agent will hand off appropriately. Simple order status queries can be answered by checking Shopify, but a complicated complaint or request might be routed to the Customer Service Agent or flagged for human follow-up. The integration with CopilotKit likely allows seamless transfer or recording of conversation transcripts for a human agent to review if needed.

Customer Service Agent

Role/Purpose: Acts as an AI support representative, focusing on post-purchase customer needs and issue resolution. This agent handles inquiries such as order status, returns, refunds, product issues, and general FAQs about store policies. The goal is to provide instant, accurate support answers and only escalate to human support when necessary, thereby improving customer satisfaction and reducing workload on human staff.

Key Responsibilities:
	•	Customer Queries & Issue Resolution: The agent interacts with customers via chat or email (it could be the same chat interface or a separate support channel). Typical questions include: “Where is my order? It hasn’t arrived.”, “I received my print but it’s damaged, what do I do?”, “How do I return a print?”, or “Can you help me track my shipment?”. The Customer Service Agent uses Shopify tools to lookup the order by number or customer email (get-order or track-order-status if available). For a status query, it will respond with shipping updates (e.g. “Your order #1234 was shipped on Oct 5th via UPS – here’s the tracking link…”). For returns or damages, it knows the store’s return policy and can guide the customer: “So sorry to hear that. Yes, we can replace a damaged print. I’ve initiated a return for you – you’ll get a return shipping label via email. Once you drop it off, we’ll send a new print.” If possible, the agent could use Shopify’s return or refund APIs to actually create a return request or refund in the system, but often it may log it for a human to finalize.
	•	Tool Usage: The Customer Service Agent relies heavily on real-time data from Shopify (and possibly Pictorem for production status). For example, to track an order’s shipment, it might use a tool to get the fulfillment details (tracking number and carrier) from the order. To process a return or exchange, it might create a draft order or a return authorization using Shopify MCP. The agent might also query the Pictorem Agent (or via Shopify tags) to see if a replacement order has been initiated for a damaged item. Additionally, it can answer policy questions by either having a knowledge base in its prompt (common FAQ answers could be embedded) or by retrieving a stored answer from a knowledge base (possibly via a tool if one exists for knowledge retrieval).
	•	Escalation and CRM Integration: If the agent encounters an issue it cannot solve autonomously (for example, a very angry customer, a complex situation like an address change after shipment, or a request for a bespoke solution outside policy), it will escalate. “Escalation” might involve creating a ticket in a CRM/helpdesk or alerting the human team. The agent might tag the customer in Shopify or a CRM with something like “NeedsHumanSupport” and summarize the conversation so far. It could also directly ping the Sales Agent or Business Manager if it’s a revenue opportunity (e.g., customer says they would buy more if a certain size were available – the service agent could inform sales or management about this lead). The Customer Relationship Agent’s profiles can inform the Service agent too: if a high-value customer has an issue, the agent will handle with extra care (maybe offering a discount for the trouble or priority service) because it knows the lifetime value (from tags/notes).
	•	Consistent Tone and 24/7 Support: This agent maintains a polite, empathetic tone, as it’s the voice of customer support. It apologizes for inconveniences and assures the customer of a solution, reflecting VividWalls’ commitment to quality. Operating constantly, it gives customers immediate answers rather than waiting for business hours responses. All interactions and resolutions are logged (via n8n or CRM integration) to maintain history. By preserving context (previous queries, provided info), the agent contributes to continuous conversations, so even if a customer returns later, the context can be remembered ￼ ￼. Ultimately, simpler issues never need human involvement, while more complex ones are neatly handed over with context, thereby improving efficiency.

Customer Relationship Agent (CRM Analyst)

Role/Purpose: Functions as a customer data analyst and relationship manager behind the scenes. This agent aggregates and analyzes customer data from Shopify (and potentially other touchpoints) to build rich customer profiles. Its output is used to personalize sales and support interactions and to inform marketing and loyalty strategies. It essentially plays the role of an AI-driven CRM system tailored for VividWalls.

Key Responsibilities:
	•	Customer Profile Building: The agent routinely pulls data on customers and compiles profiles: purchase history, total spend, products bought, browsing behavior if available, etc. For each customer, it can summarize key information such as: “Customer: Jane Doe. Total Orders: 3 (2024-2025). Total Spend: $1200. Prefers: Large canvas prints, Abstract themes (bought ‘Fractal’ and ‘Mosaic’ collections). Last Purchase: 2 months ago. Engagement: Opened last newsletter, clicked Instagram ad in September.” These profiles help in understanding each customer’s relationship with the brand. The agent might run daily or weekly, updating profiles with any new order or interaction.
	•	Segmentation & Tagging: Using Shopify’s customer data tools, the agent can classify customers into segments. For example, it identifies “VIP” customers (those who spent above a certain amount or made multiple purchases), “Recent First-Time” customers, “Churn Risk” (customers who bought once a long time ago and never returned), etc. The agent then tags customers in Shopify accordingly (leveraging the MCP tool to add tags to customer accounts ￼). These tags (like “VIP”, “RepeatBuyer”, “Hobbyist”, “HighValue”, “NeedsFollowUp”) are visible to the Sales and Service Agents when they pull customer info, enabling personalization (e.g., greeting a VIP with thanks for their loyalty, or knowing to handle a “Churn Risk” gently and maybe offer an incentive to return).
	•	Insights to Other Agents: The Customer Relationship Agent shares its findings in two ways: updating data in Shopify (tags/notes as above), and generating reports or recommendations. It might, for instance, generate a weekly CRM report for the Business Manager and Marketing agents: “We have 5 new VIP customers this month (listed by name), consider sending a thank-you note or including them in a loyalty reward campaign. 10 customers have items in cart but no purchase – Sales Agent should follow up if possible via email.” If integrated with an email tool, it could even draft personalized follow-up emails to re-engage certain customers (though sending them might be done via a marketing platform). The agent could also flag opportunities: “Customer X has bought 3 pieces from the ‘Symmetry’ series; likely to be interested in the upcoming ‘Angles’ collection – Sales should reach out when that launches.”
	•	Data Sources: The primary data comes from Shopify (order history, customer records). It might also incorporate marketing data if accessible – e.g., which campaign or ad a customer interacted with (if UTM tags or Shopify attribution data exist). If VividWalls has a newsletter or any off-Shopify interactions, those could be fed in via n8n for the agent to include. The agent may use tools like ${get-customer-orders} to retrieve all orders of a customer, or ${get-customers} to iterate over the customer base. It then applies logic or even clustering algorithms (embedded in its prompt reasoning) to segment customers. This is a form of AI-driven RFM (Recency, Frequency, Monetary) analysis done in natural language.
	•	Improving Customer Experience: By maintaining a central memory of customer interactions and preferences, this agent helps ensure that all other customer-facing agents have the context they need. It’s akin to the system storing conversation context for returning customers, but at a higher level across channels ￼. For example, if a customer complained in the past about something, a note from CRM agent would let the Service agent address it proactively if the customer comes back. If a VIP customer is chatting, the Sales agent (via a quick lookup tool or because the CRM agent pre-fetched context) can greet them with familiarity. This agent thus closes the loop between raw data and actionable intelligence within the MAS.

Social Media Advertising Agents (Facebook, Instagram, Pinterest)

Role/Purpose: These platform-specific agents handle advertising operations on their respective social networks. Each acts as a specialist for one channel – Facebook Ads, Instagram, or Pinterest – interfacing with the platform’s API via MCP to create and manage ad campaigns. They work under the guidance of the Marketing Campaign Agent, but also perform ongoing optimizations and data gathering specific to their channel. Separating them ensures that channel-specific nuances (ad formats, audience insights, best practices) are handled expertly by each agent.

Key Capabilities & Responsibilities:
	•	Campaign Execution on Platform: When the Marketing Campaign Agent decides to run a campaign on Facebook, it delegates the detailed execution to the Facebook Agent. The Facebook Agent uses the Facebook Ads MCP server (connected to Meta’s advertising API) to set up the campaign structure: it creates the campaign container, ad sets (with targeting like demographics, interests, lookalike audiences), and the ads themselves (linking images/videos and ad copy text provided by the campaign plan) ￼. Similarly, an Instagram Agent would handle creating Instagram-specific ads or promoted posts. (Note: In practice, Facebook’s Ads API covers Instagram ads too, but we treat the Instagram Agent as handling perhaps organic Instagram content as well – e.g. scheduling posts or story ads that might not be created through the Ads Manager interface.) For Pinterest, the Pinterest Agent would use a Pinterest MCP or API to create Promoted Pins or regular pins for campaigns.
	•	MCP Tool Use: Each agent uses its platform’s MCP tools:
	•	The Facebook Agent can call tools to create campaigns, fetch campaign analytics, pause or adjust campaigns, etc. It has programmatic access to “ad accounts, campaigns, ad sets, ads, and creatives,” and can retrieve performance insights and manage the ads data ￼. For example, it might use ${create-ad-set} and ${create-ad} functions with parameters like audience criteria and creative media IDs.
	•	The Instagram Agent, if separate, might use tools for posting content to Instagram or creating story ads. If using Meta’s unified ad platform, it leverages the same tools as Facebook Agent but with placement = Instagram. If focusing on organic Instagram, it could use an Instagram Graph API MCP to publish posts or get engagement stats.
	•	The Pinterest Agent uses a Pinterest MCP or custom integration. Currently available MCP functionality includes searching images on Pinterest ￼, but for ad operations, a custom extension might be needed. The agent can post new pins (with product images linking back to VividWalls), perhaps create Pinterest ad campaigns targeting certain keywords or audiences interested in art and home decor.
	•	Performance Monitoring and Optimization: After launching ads, each platform agent monitors its channel’s performance data continuously or on a schedule. They retrieve metrics like impressions, clicks, click-through rate (CTR), conversions (if tracked), and cost per result. If a campaign underperforms on their platform, the agent can autonomously suggest optimizations. For instance, the Facebook Agent might notice one ad set is getting a poor CTR and decide to reallocate budget to a better-performing ad set or tweak the audience (via function calls to update targeting). The Pinterest Agent might find that pins with certain keywords get more repins and adjust the content strategy accordingly. These agents essentially act as mini marketing AIs focusing on their specific channel’s best outcomes. They can report summary results and any changes back to the Marketing Campaign Agent or Business Manager.
	•	Coordination with Marketing Campaign Agent: Initially, the Marketing Campaign Agent provides these agents with campaign parameters (budget, duration, creative assets, messaging). The platform agents execute accordingly and then keep the Campaign agent informed (possibly via n8n messaging or by updating a campaign status that the Campaign agent can query). For example, after creation, the Facebook Agent could return the campaign IDs or links, which the Campaign agent logs. During campaign run, if the Business Manager queries “How are our campaigns doing?”, the Campaign agent might ask each platform agent for a quick update, which they provide from the latest metrics. This modular approach means the Marketing Campaign agent doesn’t need to know the intricacies of each ad platform; it relies on the platform agents for that, embodying the principle of vertical specialization in the MAS ￼.
	•	Adherence to Platform Policies: Each platform has its own advertising policies and best practices (image aspect ratios, text length, prohibited content, etc.). These agents are fine-tuned (or instructed) with that platform knowledge, reducing the chance of an ad being disapproved. For instance, the Facebook Agent knows not to put too much text on an image (to avoid low reach), and the Pinterest Agent knows the optimal times to post pins. By encapsulating this knowledge, the MAS ensures campaigns run smoothly across all channels without requiring the central system to micromanage each nuance.

Workflows

The MAS operates through n8n workflows that trigger agents based on specific conditions or schedules. Below are the key workflows, detailing triggers, agent orchestration, and data flow between agents:

1. Marketing Planning & Campaign Launch Workflow

Trigger: Time-based (e.g. the first day of each month at 9 AM) or manual trigger by the Business Manager Agent if an immediate strategy update is needed (such as after a major market change or new art collection release). This could also trigger quarterly for a bigger planning session.

Sequence:
	1.	Marketing Research Phase: The Business Manager Agent (via n8n scheduler) activates the Marketing Research Agent with a prompt to generate a new marketing plan. The workflow passes in any relevant context – e.g. last month’s sales summary (fetched via ${get-orders} by the Shopify Agent beforehand) and known upcoming events (maybe provided as static input, like “Holiday season in Dec-Jan” or “New collection ‘Symmetry’ launching next week”). The Marketing Research Agent uses this input plus external research to produce a 3-month campaign plan as described earlier.
	2.	Review & Delegation: The output (campaign plan) is fed back to the Business Manager Agent. The Business Manager reviews the plan. If it’s satisfactory, it proceeds; if it needs tweaks, the Business Manager could either adjust it or send a feedback prompt to Marketing Research for refinement (this would be a secondary loop in the workflow). Assume it’s approved. The Business Manager then formulates an instruction to execute the plan, effectively triggering the Marketing Campaign Agent. For example, it might send a structured summary: “Approved Campaigns: (a) Autumn Refresh in Oct on FB/IG, budget $500; (b) Holiday Gift Guide in Nov on FB/Pinterest, budget $800; (c) New Year New Art in Jan on IG/Pin, budget $600. Use creatives X, Y, Z.” This serves as the input for the campaign execution phase.
	3.	Campaign Execution Phase: The Marketing Campaign Agent now runs. n8n ensures this agent has the plan details (passed from the previous step). The agent goes through each campaign item in the plan and for each platform involved, it either calls the respective MCP tools directly or triggers the platform-specific agents. For instance, for the October Facebook campaign, the Marketing Campaign Agent might directly call the Facebook MCP via an embedded ${create-campaign} function (if it has the tool integrated in its prompt). Alternatively, n8n can invoke the Facebook Agent node, providing it with the campaign parameters. In either case, the Facebook campaign is created. The same happens for Instagram and Pinterest – either via their agents or direct tool calls. The workflow can either iterate or run parallel branches for each platform to speed up execution.
	4.	Asset Coordination: If there are any content assets needed (images, ad copy) that weren’t generated yet, the Marketing Campaign Agent (or platform agents) handle those. Ad copy is generated by the LLM on the fly. Images (the artwork photos) are likely already available – the agent can retrieve the image URLs from Shopify for the product it’s advertising (Shopify’s API can provide images for a product). If needed, n8n could facilitate downloading or converting images. All creatives and text are then uploaded via the platform APIs in the campaign creation calls.
	5.	Confirmation & Logging: After all campaigns are launched, the agents return success confirmations (e.g. campaign IDs, or URLs to view the ads). The workflow compiles a summary report. The Business Manager Agent might be triggered one more time to log the outcome: e.g., “Campaigns launched: Facebook Campaign ID 12345 (Oct refresh), Pinterest Promoted Pins ID 98765 (Holiday guide)…”. The Business Manager can then close out the workflow by perhaps sending a notification (could email the business owner or just log internally).

Inter-agent Communication: Within this workflow, data flows from Research Agent -> Business Manager -> Campaign Agent -> Platform Agents/Tools. n8n acts as the messenger, taking the text output from one agent and providing it as input to the next. Agents also share data via structured formats: the Marketing Research Agent might output the plan in a JSON-like structure or bullet list, which the Business Manager and Campaign Agent can parse. Similarly, the Campaign Agent might output a list of created campaigns with identifiers which the Business Manager logs or uses to schedule Monitoring workflows (below).

2. New Collection Launch Workflow

Trigger: Event-based (whenever a new art collection or series is added to the catalog) or manually triggered when the business is about to launch a collection. This could be initiated by an admin adding products tagged as “new collection” in Shopify, which triggers a webhook.

Sequence:
	1.	Detection: Suppose a VividWalls admin (or possibly an AI design agent) adds a new collection “Floral Abstracts” with 5 new prints. A Shopify webhook for “new products/collection” fires and n8n catches it. The workflow activates the Business Manager Agent with context about the new collection (like name, theme, number of pieces, any initial description).
	2.	Planning: The Business Manager knows a new collection launch should be accompanied by marketing. It may immediately task the Marketing Research Agent to do a quick analysis specific to this collection (e.g. research current interest in floral art or similar topics to craft a campaign angle). However, if that’s redundant (the monthly plan could handle it), the Business Manager might skip straight to execution. Let’s assume this is a special launch needing extra buzz – the Business Manager instructs the Marketing Campaign Agent to “launch a campaign for the new ‘Floral Abstracts’ collection” with certain budget and ASAP timing.
	3.	Campaign Execution: The Marketing Campaign Agent works similarly to above, but focused on this single collection. It might create a special Facebook/Instagram campaign highlighting “New Arrival: Floral Abstracts – limited edition prints.” It will likely use high-level targeting (maybe retarget recent site visitors or existing customers tagged as interested in similar styles). It calls the Facebook Agent and Instagram Agent to create these ads quickly (since timeliness is key for a launch). It might also schedule a couple of organic social posts via Instagram Agent for followers (if VividWalls has social media presence). Pinterest Agent could create a new board or pins for the collection. Additionally, the agent could coordinate a small email campaign if an email tool integration exists (not in the core spec, but possibly via another node, outside this agent system).
	4.	Shopify Updates: The Shopify Agent might be called to ensure the new collection is properly featured on the homepage or in a featured collection section. The Business Manager or Marketing Campaign agent could tell Shopify Agent: “Promote the new collection on store” – which could involve reordering homepage sections or adding a banner (if accessible via an API or theme customization). If not automated, at least a discount code specifically for the new collection can be created by Shopify Agent (like “FLORAL10” for first buyers) and that code is used in marketing messages.
	5.	Coordination with Pictorem: Because this is a new set of products, the Pictorem Agent might be engaged to verify that the product specs match Pictorem’s offerings (print sizes, etc.) and maybe pre-fetch costs. It can use Pictorem’s pricing API to check all new SKUs. If any configuration isn’t valid (say a size that Pictorem can’t print), the agent alerts the Business Manager to adjust the offering. This step ensures fulfillment can actually deliver what is being sold in the new launch.

Outcome: In a short span, right after a new collection is added, the system automatically kicks off marketing so the collection gets immediate exposure. This workflow showcases reactivity: the MAS doesn’t wait for the monthly cycle; it can respond to real-time events (product launches) with rapid marketing actions.

3. Order Fulfillment & Tracking Workflow

Trigger: Event-based, fires whenever a new order is placed on Shopify (or an order’s payment is confirmed). Shopify’s webhook (Order Creation) triggers n8n.

Sequence:
	1.	Order Intake: n8n receives the new order data (order ID, items, customer info). It first triggers the Shopify Agent (or directly uses a Shopify node) to fetch full order details via ${get-order} (including line items, customizations, shipping address). This ensures we have everything needed for fulfillment.
	2.	Fulfillment Coordination: The workflow invokes the Pictorem Agent next, supplying the order details. The Pictorem Agent’s prompt receives all relevant info (which product, size, frame, shipping address, etc.) and it proceeds to call Pictorem’s API to place the production order. If the Pictorem Agent successfully creates an order, it gets back a confirmation (maybe an order number on Pictorem’s side). It might also get an estimated ship date. The agent then updates the order status: it can call Shopify’s API (possibly via Shopify Agent) to mark the order as “in production” or simply add an order note like “Sent to Pictorem on [date] Order#[XYZ]”.
	3.	Customer Update: Optionally, the MAS could send a customer a confirmation that their order is being produced. Shopify typically already sends an order confirmation email upon purchase. The Pictorem Agent might not need to send anything at this stage beyond ensuring Shopify reflects that fulfillment is pending. However, if there’s a significant production time, some stores send a “your item is being handcrafted” email. The Business Manager could trigger an Email node or have the Customer Service Agent send a message if appropriate (this part may be handled outside the LLM agents via Shopify’s notification system or Klaviyo, etc., but it’s noted as a possible extension).
	4.	Tracking & Completion: When Pictorem finishes and ships the order, the workflow needs to catch that event. Two possibilities: (a) Polling – an n8n scheduled job triggers the Pictorem Agent daily to check for any shipped orders (using a ${get-orders-update} from Pictorem API to get tracking numbers for recent orders) ￼. (b) Callback/Webhook – if Pictorem can send a webhook when an order ships, n8n could capture it and trigger directly. Assuming polling for simplicity: the Pictorem Agent finds order #XYZ now has tracking # and status “shipped”. It then calls the Shopify Agent to update the Shopify order: marks it as fulfilled, enters the carrier and tracking number. Shopify will then send the customer a “Your order has shipped” email with tracking info. The workflow is thus completed for that order.
	5.	Exception Handling: If any step fails (e.g. Pictorem API is down or returns an error), the Pictorem Agent signals an error. n8n can catch this and notify the Business Manager or a human. Meanwhile, the order remains unfulfilled in Shopify, which the support team can see. The MAS might retry automatically after some minutes for transient issues. Similarly, if after a certain time no shipping info is returned (indicating a delay at Pictorem), the Customer Service Agent could proactively reach out to the customer to apologize for delay or provide an update (if it’s aware; likely Business Manager would schedule such a task if Pictorem lead times exceeded SLA).

Inter-agent Data Flow: This workflow primarily involves Shopify Agent -> Pictorem Agent -> back to Shopify Agent. The Customer Relationship Agent may also be pinged here: once an order is completed, the CRM agent can update the customer’s profile (e.g., increment purchase count, etc.). n8n could branch the flow: after fulfillment steps, call the CRM Agent to refresh that customer’s data (so tags like “NewCustomer” might drop, or “RepeatBuyer” tag added if this was their second purchase). Additionally, if the order was from a new customer, the Sales Agent could be informed to greet them if they come to chat (“Thanks for your first purchase!”), though that’s more dynamic. The key is all relevant agents get updated that an order happened and was fulfilled.

4. Inbound Sales Inquiry (Chat) Workflow

Trigger: Event-based, initiated when a user engages the chat on the website (Shopify or WordPress). This is a bit different as it’s a live interactive session rather than a linear workflow, but we can describe the agent interaction pattern.

Sequence:
	1.	User Message Received: The website’s chat (CopilotKit) captures the visitor’s message (e.g. “Hi, I’m interested in large wall art”). This is sent to the Sales Agent. In an n8n context, this could be handled by a persistent WebSocket or API call to an “AI Agent” node that holds the Sales Agent’s chain. Essentially, the Sales Agent is always “on” listening for messages (not purely event-triggered like the others). However, for specification, we note that each user message triggers the Sales Agent to respond via its LLM prompt, with conversation context maintained.
	2.	Sales Agent Responds with Tool Use: The Sales Agent analyzes the query. Perhaps it decides to show the user some large prints. It calls ${get-products} (via Shopify MCP) with a filter for large size or a certain collection. n8n (or the CopilotKit backend) executes this function call and returns product data (titles, images, prices). The Sales Agent then composes a helpful answer: “We have several large-format prints. For example, Vivid Mosaic no4 – a vibrant abstract piece, available up to 60x40 inches. It comes ready-to-hang in a floating frame. Another popular choice is Dark Kimono from our Geometric Symmetry collection ￼. Would you like to see an image or learn more about either of these?” It may even use an embed_image tool if the chat supports sending an image, to show a thumbnail of the art.
	3.	Customer Follows Up: Suppose the user asks to see Vivid Mosaic no4 in detail. The Sales Agent might then retrieve that specific product (get-product by ID or title) to get its description and available sizes. It then shares: “‘Vivid Mosaic no4’ is a limited edition print that features a labyrinth of rich crimson and purple hues ￼. It’s signed by the artist and only 50 pieces will ever be made. We offer it in 3 sizes: 24x32, 36x48, and 40x60 inches. The price for the large 40x60 (including the thin black floating frame) is $400. It would make a stunning focal point in a living room.” This answer combines data and persuasive language.
	4.	Conversion Attempt: If the customer is interested, they might ask about purchasing or shipping. The Sales Agent can then assist with the transaction. For instance, the user says “Sounds great, how do I buy it?” The agent can respond with a direct checkout link: it could use a tool like ${create-cart} or ${create-draft-order} in Shopify via the MCP. The agent would input the product variant for 40x60, the user’s email (if provided or ask for it), and generate either an invoice link or populate the user’s cart (if the chat is on the site, it might be able to inject into their current session’s cart). It then replies: “I’ve added ‘Vivid Mosaic no4 (40x60, Black Frame)’ to your cart for you. You can Proceed to Checkout now. Let me know if you need any help during checkout!”. If the user wants a discount, the agent could generate one-time code and apply it.
	5.	Closure & Follow-up: Once the user either purchases or leaves, the chat conversation might end. The Sales Agent (through CopilotKit) can record the conversation outcome. If a sale was made, great. If not, and the user provided contact info or seemed very interested, the system could follow up later (maybe the CRM agent logs an abandoned cart or lead). In an advanced scenario, the Sales Agent could send a “Thank you for chatting” email with the items discussed. Also, context from this conversation (preferences, items viewed) can be fed to the Customer Relationship Agent to refine that user’s profile (even if they didn’t buy, it’s useful data – e.g. mark them interested in “Mosaic collection”).

Agent Orchestration: This workflow primarily involves the Sales Agent doing both conversation and tool usage. It pulls data via Shopify Agent as needed. If a question veers into support (like “I haven’t received my order”), the Sales Agent might either handle it (it can check order status) or invoke the Customer Service Agent. In practice, the same chat interface could route the user to a specialized agent based on intent (n8n or CopilotKit might detect the query as a support vs sales query and assign to the appropriate agent). If the Sales Agent is handling and it realizes this is a support issue beyond sales scope, it can transfer by yielding control to Customer Service Agent (this could be achieved by an internal flag or the Business Manager deciding to switch agents). From the user’s perspective, it might just continue seamlessly, or a message “Let me have our support specialist assist you” could appear. This interplay ensures the user always gets the most qualified response.

5. Customer Support Ticket Workflow

Trigger: Multi-channel event – could be a direct chat labeled as support, an incoming email to support@vividwalls, or a form submission on the Contact page. For chats on the site, as mentioned, the system might route to Customer Service Agent if the intent is clearly a support issue. For emails or contact form, n8n can trigger when those are received (if integrated via email IMAP or a form webhook).

Sequence:
	1.	Issue Intake: Let’s say a customer sends an email: “Order #1234 – I received the wrong print.” n8n catches the new email and triggers the Customer Service Agent with the email content. The agent parses the message: it sees order #1234 and the issue. It uses ${get-order} via Shopify to retrieve order 1234 details (to confirm what was ordered originally, and perhaps any fulfillment notes). It finds, for example, the customer ordered “Mosaic no2” but perhaps Pictorem accidentally shipped “Mosaic no3”.
	2.	Agent Response: The Customer Service Agent drafts a polite apology and solution: “Hello [Customer Name], I’m sorry to hear you received the wrong print. It looks like you should have received Mosaic no2 but got a different item. I have initiated a replacement order for the correct print and prioritized its fulfillment at no extra cost. You’ll receive a new tracking number soon, and you can keep the other print as our apology, or donate it if you wish. Thank you for your patience!”. Before sending that, the agent actually does what it promised: it can use the Pictorem Agent to place a replacement order for Mosaic no2 immediately (or use Shopify to create a new order marked as replacement, which triggers Pictorem Agent). It might also generate a unique discount (or gift card) as a goodwill gesture for the next purchase and include it in the email (“Here’s a 20% off code for your next order”).
	3.	Escalation if Needed: If the agent cannot find order 1234 or something is inconsistent (say the customer is mistaken or the issue is complex), it may escalate. It could respond with a holding message and flag a human: “Thank you for contacting us. I’m escalating this issue to a specialist who will get back to you shortly.” Then it sets a flag for manual review (e.g., sends an email to support staff or creates a ticket in a system like Zendesk via an integration node). For severe cases (like fraud suspicion), Business Manager might also be alerted.
	4.	Follow-up Workflow: After resolving or escalating, the system might trigger the Customer Relationship Agent to update the customer’s profile (e.g., add a tag “IssueResolved” or note about wrong item incident). This ensures that if the customer comes back in chat or another purchase, the Sales or Service agent can be extra attentive. The Business Manager might also keep track of such incidents for quality control with Pictorem. If a trend is detected (multiple wrong prints), it might prompt an operational change.

Integration: In this workflow, the Customer Service Agent often interacts with Shopify (orders) and may spawn the Pictorem Agent for replacements or returns. It may also use an email-sending tool (if not directly replying via some connected email channel). n8n would handle sending the email response that the agent composes. The workflow ensures the customer gets a timely response (likely within minutes of sending the email or instant on chat) with concrete actions taken, demonstrating the benefit of AI agents in support. Human intervention is only looped in when the AI either doesn’t understand the issue or lacks permissions (like issuing a large refund might require human approval).

6. Customer Data Enrichment & Outreach Workflow

Trigger: Scheduled (e.g., daily at midnight) or event-based after certain triggers (like after each order completion, or a new customer signup).

Sequence:
	1.	Profile Update Batch: Suppose it’s a nightly schedule. The Customer Relationship Agent is triggered to update profiles for the day’s events. It might retrieve all customers who had new orders today (via Shopify get-orders filtering today and extracting unique customer IDs). For each such customer, it calls ${get-customer} to get their current info and order history. It then updates their internal profile reasoning and decides if any segment tag changes are needed. For example, Customer A made their 3rd purchase today, so now they qualify as a VIP – the agent issues a ${add-tag} for “VIP” on that customer. Customer B made a first purchase – agent tags “NewCustomer”. Customer C hasn’t purchased in 12 months (the agent might check last order date) – agent tags “AtRisk”. This can be done in a loop in n8n or within the agent (though doing many in one LLM call might be tricky, so likely n8n iterates customers and calls the agent for each or small batches).
	2.	Insight Generation: After updating data, the agent produces any notable insights or action recommendations. For instance: “5 customers have spent over $1000 – consider sending thank-you packages. 12 new customers this week – Marketing should send welcome emails. 3 high-value customers haven’t bought in 6+ months – maybe target them with a win-back campaign on Facebook.” This report is passed to the Business Manager agent or directly emailed to the business owner/marketing team as a summary.
	3.	Outreach Automation (optional): The workflow can directly trigger outreach based on the CRM agent’s output. For example, if the agent specifically outputs “Send loyalty discount to VIPs: [list of emails]”, n8n can feed that into an Email node or another agent to draft those emails. Similarly, a list of “churn-risk customers” can be fed to the Marketing Campaign Agent to create a custom audience on Facebook (via the Facebook Agent uploading those emails as an audience, then running an ad targeting them with a special offer). This demonstrates closed-loop automation: the insight immediately becomes an actionable campaign.
	4.	Data Loop: The updated tags and notes on customers are now in Shopify, so next time the Sales or Service agents query a customer, they see the latest info. The CRM agent might also maintain an internal database (or simply rely on Shopify as the database of record with tags and metafields for additional data).

Inter-agent Communication: The CRM agent interacts with the Shopify Agent for data retrieval and updates. It informs the Business Manager and Marketing agents of its findings. In some implementations, the CRM agent’s work might not involve a “User” query at all – it’s autonomously doing analysis. In n8n, this might be done with an LLM node where the system message says “Summarize customer data changes today…” and user message provides raw data. The result is then parsed for actions. The Business Manager agent might parse the CRM’s text and then trigger follow-up workflows (like initiating a marketing campaign or tasking the Sales agent to personally reach out to someone if needed via email or chat). This workflow keeps the MAS proactive – not only reacting to events but also seeking opportunities from data patterns.

Tool Integration Map

A variety of MCP tools and integrations empower the agents to perform their tasks. Below is a map of the key tools (grouped by service) and which agents use them, as well as notes on new tools to be developed:
	•	Shopify MCP Server (Storefront API Tools): This provides structured access to all of VividWalls’ store data and operations via Shopify’s GraphQL Admin API. It includes tools for product queries, collection management, customer data, order operations, discounts, and more ￼. Key tools and their usage:
	•	get-products / search-products: Retrieve product information (used by Sales Agent to answer product questions, by Marketing Agents to select campaign items, by Shopify Agent for store updates).
	•	get-products-by-collection: List products in a specific collection (used in marketing to target a collection, or by Shopify Agent to assemble collection pages).
	•	get-collections: Retrieve list of collections (used by Marketing Research Agent to see what categories exist, etc., and by Shopify Agent for organizing products).
	•	get-orders / query-orders: Fetch orders with filters (used by Business Manager for sales analytics, by CRM Agent to find recent purchases, by Service Agent to find a specific order’s details).
	•	get-customer / list-customers: Fetch customer details (used by Sales/Service Agents during conversations to personalize service, and by CRM Agent to build profiles).
	•	add-tag-to-customer: Add tags to a customer (used by CRM Agent to mark VIPs, etc., potentially by Service Agent to flag an issue or by Sales Agent to mark a lead).
	•	create-draft-order / create-cart: Create an order or cart (used by Sales Agent to facilitate checkout from chat, or by Service Agent to create a replacement order in a support case).
	•	create-discount: Generate a discount code (used by Marketing Campaign Agent to support promotions, or Sales/Service Agent to provide goodwill coupons).
	•	update-product (price or details): Modify product info (used by Shopify Agent, e.g., when updating prices based on Pictorem costs or when publishing a new collection’s info).
	•	Agents: Shopify Agent is the primary user of these tools for direct store management tasks, but Sales, Customer Service, Marketing Campaign, and CRM Agents also invoke Shopify MCP tools via the Shopify Agent or directly in their prompts, whenever they need store data or to perform a store action. Essentially, Shopify’s MCP is central to many agent interactions as the source of truth for product and order info ￼.
	•	Pictorem Integration (Print Fulfillment API): Pictorem’s Print-on-Demand API allows the MAS to handle fulfillment tasks programmatically ￼. Key capabilities include:
	•	Product Catalog Access: Tools to get product listing and pricing for various print formats (canvas, metal, acrylic, etc.) ￼. Pictorem Agent uses this to ensure VividWalls’ product offerings and pricing align with Pictorem’s options and costs. If a new format is introduced, the agent can fetch it and inform the Business Manager (e.g., “Pictorem now offers Wood prints, do we want to add those?”).
	•	Order Placement: Endpoint to place an order with Pictorem, including uploading image file and providing customer shipping info ￼. The Pictorem Agent uses this for every customer order from Shopify, effectively automating the dropship request.
	•	Order Status & Tracking: Tools to get order production status and retrieve tracking numbers ￼. The agent polls or listens for updates, then updates Shopify orders accordingly.
	•	Possibly Cost Estimation: A tool to calculate cost of an item (if not directly given, the agent can retrieve pricing and do math). This helps in pricing strategy and checking margins.
	•	Agents: The Pictorem Agent is the direct consumer of these tools. The Business Manager Agent might also call on Pictorem data indirectly (for example, asking “what’s the average fulfillment time lately?” which the Pictorem Agent would answer by checking statuses). The Customer Service Agent might use Pictorem info when informing customers of production delays or checking if an order has shipped from Pictorem’s side (though usually Shopify is updated, but if not yet, it could query Pictorem). If Pictorem’s MCP server is not readily available, development is needed to wrap their REST API in an MCP interface. This is a required integration to fully automate fulfillment.
	•	Facebook Ads MCP Server: Provides the MAS with tools to manage Facebook (Meta) advertising campaigns through function calls ￼. Key tools likely include:
	•	create-campaign: Create a new advertising campaign (with objectives like conversions or traffic).
	•	create-ad-set: Define targeting, budget, and schedule for a set of ads under a campaign.
	•	create-ad: Upload creative and text to produce an ad under an ad set.
	•	get-campaign-insights: Retrieve performance metrics (impressions, clicks, spend, conversions) for analysis.
	•	update-campaign or pause-campaign: Manage the campaign’s status (used by platform agents for optimizations or to stop ads after budget is spent or goal achieved).
	•	Possibly get-audiences or create-audience: to retrieve saved audiences or create custom ones (for example, using customer list from CRM Agent to create a lookalike audience).
	•	Agents: The Facebook Agent primarily uses these tools. It executes instructions from the Marketing Campaign Agent to set up campaigns and also might autonomously call get-campaign-insights to report performance. The Marketing Campaign Agent itself might invoke some of these directly if it handles initial setup; however, given the design, it will likely rely on the Facebook Agent. (The Instagram Agent could also use Facebook’s tools if dealing with Instagram Ads, since those are integrated in Meta’s platform.) Prompt Engineering Foundation

To enable these agents to function reliably, careful prompt engineering is employed. All agents use tool-enabled LLM prompts that include clear instructions, role definitions, and the availability of MCP function calls. Below are best practices and templates used across the MAS:

General Best Practices for Tool-Using Prompts:
	•	Role Specification: Each agent’s system prompt explicitly defines its identity and objectives. For example: “You are the Marketing Research Agent, an expert in analyzing art market trends and planning marketing campaigns for an art prints e-commerce. Your goal is to propose effective campaigns that increase sales.” This ensures the LLM stays in character and focuses on relevant tasks.
	•	Tool Description and Syntax: The prompt includes a list or description of the tools (functions) the agent can use, with the exact syntax for calling them. For instance, the Shopify tools might be listed as: “Tools available: ${get-products(searchTitle: string)} – search products by title; ${get-orders(since: date)} – retrieve orders since a date; …”. By providing this in the prompt (often as a system or developer message), the LLM knows how to format a function call. It’s important to format tool invocation exactly, e.g. ${toolName(param: "value")}, so the system (n8n or MCP client) can detect and execute it.
	•	Chain-of-Thought and Tool Use Guidance: Agents are prompted to reason about when to use a tool. A common pattern is to have the agent think step-by-step. For example, the prompt might say: “If you need data to answer or complete your task, use the appropriate tool. First, explain what you intend to do, then call the tool in the format ${...}. Once you get the result, incorporate that into your response.” This encourages the model to first attempt to gather information via MCP calls rather than guessing. For instance, the Sales Agent’s prompt might instruct: “Always check product availability via the tools before confirming details to a customer.”
	•	Output Formatting and Clarity: The prompts guide the agent on how to format the final answer. For customer-facing agents (Sales, Service), the answers should be polite, concise, and helpful, without exposing the raw tool output unless appropriate. For backend agents (Campaign, CRM), the output might be structured data or a report. We ensure the prompt clarifies this: e.g., Marketing Research Agent might be told to output a numbered list of campaign ideas with brief descriptions. Consistency in formatting makes it easier for n8n to parse or for humans to read the results.
	•	Avoiding Hallucination: Since the agents have tools, the prompts remind them not to fabricate data that can be fetched. For instance: “If a customer asks for order status, do not guess – use the ${get-orderStatus(orderId)} tool to retrieve the real status.” Also, the agent should refrain from calling tools that aren’t relevant (the prompt can include instructions like “Only use a tool if it’s necessary for your response; if you already have sufficient information, proceed to answer directly”). This prevents frivolous API calls and keeps conversations efficient.

Embedding MCP Function Calls in Prompts:
Agents embed function calls directly in the text of their “thought” or response, which the system intercepts. The syntax used is ${...} as a placeholder for the function name and arguments. Some guidelines for this mechanism:
	•	Agents typically first produce a reasoning statement like “Let me check our inventory for that item.” followed by on a new line the function call, e.g. ${get-product(productId: "gid://shopify/Product/123456")}. The presence of ${} tells the MCP client (in our case, likely n8n integrated with the MCP servers) to execute that function.
	•	The prompt instructs agents to only use the exact function name and parameter schema as given, and to wrap it in ${}. They should not add extra commentary inside the braces. For example, correct usage: ${get-orders(limit: 5)}, incorrect would be forgetting braces or misnaming.
	•	After execution, the function result (often in JSON or a text snippet) is fed back into the conversation. Agents are prompted on how to handle results – e.g., “The tool will return data in JSON. You should interpret that and continue the conversation.” Agents might be shown an example: if ${get-orders} returns a JSON with an order list, the agent then says “I see your last order was shipped on Oct 5th…”.
	•	Example: In the Sales Agent’s prompt, an illustrative dialogue could be given: User: “Do you have any prints of Paris?” – Assistant’s thought: “The user is asking for Paris-themed prints. I should search products.” – Assistant’s action: ${get-products(searchTitle: "Paris")}. Then the prompt shows how the result might look and how the assistant should follow up. These examples (few-shot prompting) greatly help the model use tools correctly.
	•	We ensure the system (n8n + MCP client) supports these embedded calls. This approach is in line with the Model-Context-Protocol usage: the LLM’s text contains the function call which is extracted and executed, then the result is appended to the LLM’s context (often as a pseudo “assistant message” with the data, or directly replacing the ${} in some implementations). The prompt might contain a note: “Do not reveal the function syntax or JSON to the user unless necessary – use it internally to formulate your answer.”
